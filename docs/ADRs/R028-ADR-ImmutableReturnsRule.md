# R028-ADR-ImmutableReturnsRule

- **Status:** Proposed
- **Date:** 2026-10-20

## Context

[R022](R022-ADR-ReturnedMutationsRule.md) closes one mutating channel: a
function does not write its output through a `&mut` parameter. Its mirror is
open. A function can still hand a mutable reference *out* --
`pub fn state_mut(&mut self) -> &mut State` -- and from then on the caller
changes the type's internals without passing through a single one of its
methods. Every invariant the type keeps is kept only as long as no caller uses
what it was lent.

The house standard keeps `&mut self` as the one channel through which a type
changes. A returned `&mut` is a second one, owned by whoever holds the
reference.

## Decision

**A function does not hand out a mutable reference.** Any function in `src/`
whose return type is, or structurally contains, a mutable reference is an
offence: `-> &mut T`, `-> Option<&mut T>`, `-> (&mut A, B)`, `-> &'a mut T`.

- **`&'static mut` is left alone.** A static handed over once -- the
  `StaticCell` shape an embedded executor needs for its stack resources -- is
  not a type lending its internals; there is no type.
- **Trait impls are left alone**, their signatures being the trait's:
  `DerefMut`, `IndexMut`, `AsMut`, an `Iterator` over `&mut` items. A trait
  declared in the crate is reported once, at its declaration, as R022 does.
- **A callback's contract is not descended into**: `impl FnMut(&mut T)` in a
  return type describes what the caller's closure receives, not what this
  function lends.
- **The type walk is R022's.** "Is, or structurally contains, a mutable
  reference" is the question R022 already asks of a parameter; this rule asks it
  of the return type.
- **One offence per function**, at its name. The correction: *"return the value,
  or give the type a method that makes the change"*; for `-> &mut Self`, *"take
  and return `self` by value"*.
- **Exempt:** `tests/`.

## Forcing constraints / Evidence

A census on 2026-10-20 over sixteen repositories -- the `etheram-*` six, the
seven `*4rust` tools, `slotgate`, `etheram-tools` and an analysis workspace --
read 8,425 functions under `src/`, trait impls excluded, with a heuristic scanner
validated on a file of labelled cases first. It has to be re-run with this tool's
finders before the rule ships.

Four functions return a mutable reference:

- two `&'static mut StackResources` in `etheram-embassy`'s transport
  configuration -- the static handover, left alone above;
- two `-> &mut Self` on a fluent checker in the analysis workspace.

The rule is insurance rather than a cleanup: the family already does not lend
its internals, and two offences fix by returning `Self`.

## Rejected alternatives

**Folding it into R022.** The detection is shared, but the concern is not: R022
is about where a function's *output* goes, this rule about what a type *lends*.
A repository can want one without the other, and an offence should name the one
it broke.

**Exempting `-> &mut Self` for chaining.** Rejected: a chain of `&mut Self` calls
reads as a builder and is a mutable borrow held across every call. Returning
`Self` by value keeps the chain and drops the loan.

**Reporting `&'static mut` too.** Rejected: an embedded executor requires it, the
census found it only there, and the correction would not be Rust anyone could
write.

## Consequences

**`&mut self` is the only way a type changes**, and R022 and this rule between
them make every other mutation visible in a return value.

**Two offences on the day it ships**, both in one analysis workspace.

### What this rule does not catch

- **Interior mutability handed out** -- `&RefCell<T>`, `&Cell<T>`, an
  `Rc<RefCell<T>>` -- which is mutation through a shared reference and a type
  question this tool cannot answer.
- **Raw pointers**, `*mut T`, which are `unsafe`'s business.
- **Functions generated by a macro**, invisible to `syn`.

## Enforcement

To be written test-first when the rule is built: `&mut T`, wrapped and in a
tuple; a named lifetime; `&'static mut` left alone; trait impls left alone and a
crate's own trait reported at its declaration; `impl FnMut(&mut T)` not
descended; `-> &mut Self` and its correction; `tests/` exempt; the unparseable
file; `check_workspace`, `is_configured`, the name and the requirement;
`tests/rule_registry_tests.rs` updated. This crate returns no mutable reference
today.
